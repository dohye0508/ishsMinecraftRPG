# 기획팀 가이드

코드 수정 없이 `configs/` 폴더의 `.yml` 파일만 편집해 서버 콘텐츠(스탯·레벨·보상 수치, 동아리, 스킬, 아이템, 도전과제, 문구, 맵·인증 설정, 퀘스트, NPC 대화)를 변경하는 방법입니다.

---

## 🔄 작업 흐름

1. `configs/` 안의 파일을 수정합니다.
2. `configs/배포.bat`을 실행합니다. 변경된 파일만 서버 `plugins/`로 복사되며, 덮어쓰기 전 서버 파일은 `backup_config/sync_<날짜시간>/`에 백업됩니다.
   - 적용 범위만 확인하려면 `미리보기_배포.bat`을 사용합니다.
3. 게임에서 OP 권한으로 아래 명령을 입력합니다. (서버가 꺼져 있었다면 기동만 하면 됩니다)
   - `/bq reload` — 퀘스트·대화
   - `/설정리로드` — `ishsMinecraftRpg/` 안의 모든 설정 파일
4. 서버 콘솔에 `[gameplay.yml]`, `[clubs.yml]`, `[items.yml]`, `[messages.yml]` 같은 경고가 없는지 확인합니다. (잘못된 이름·값은 해당 부분만 무시되고 경고가 출력됩니다)
5. 확인 후 Git에 반영합니다. (`git add configs` → `git commit` → `git push`)

맵(월드)을 잃어버리지 않도록 보관하려면 서버를 끈 뒤 `configs/월드백업.bat`을 실행합니다. `server/backup_world/`에 날짜가 붙은 zip으로 저장됩니다. (백업 파일은 같은 PC에만 있으니 USB나 클라우드에도 복사해 둡니다)

서버 폴더의 파일을 직접 수정한 경우에는 `서버에서_가져오기.bat`으로 `configs/`에 먼저 반영합니다. 그렇지 않고 `배포.bat`을 실행하면 서버 쪽 수정 내용이 `configs/`의 내용으로 덮어써집니다. (백업은 남습니다)

폴더 구조와 스크립트 상세는 [configs/README.md](../configs/README.md)를 참고합니다.

## 📁 편집 대상

| 대상 | 파일 (`configs/` 기준) | 적용 |
|---|---|---|
| 맵 경계·스폰, 리로스쿨 인증, `/퀘스트` 표시 이름 | `ishsMinecraftRpg/config.yml` | `/설정리로드` |
| 스탯 공식, 레벨, 보상, 게임 규칙, 월드 설정 | `ishsMinecraftRpg/gameplay.yml` | `/설정리로드` |
| 동아리 (이름, 아이콘, 가입 보너스) | `ishsMinecraftRpg/clubs.yml` | `/설정리로드` |
| 스킬 (쿨타임, 마나, 피해량) | `ishsMinecraftRpg/skills.yml` | `/설정리로드` |
| 커스텀 아이템 (이름, 설명, 기능) | `ishsMinecraftRpg/items.yml` | `/설정리로드` |
| 도전과제 (이름, 설명, 알림 문구) | `ishsMinecraftRpg/achievements.yml` | `/설정리로드` |
| 동아리 랭킹판 (크기, 문구, 갱신 주기) | `ishsMinecraftRpg/ranking.yml` | `/설정리로드` |
| 알림·안내·GUI·사이드바 문구 | `ishsMinecraftRpg/messages.yml` | `/설정리로드` |
| `/도움말` 문구 | `ishsMinecraftRpg/help.yml` | `/설정리로드` |
| NPC (위치, 이름, 스킨, 연결할 대화) | `ishsMinecraftRpg/npcs.yml` | `/설정리로드` |
| 퀘스트 목표·보상 | `BetonQuest/QuestPackages/default/main.yml` | `/bq reload` |
| NPC 대사·선택지 | `BetonQuest/QuestPackages/default/conversations/<이름>.yml` | `/bq reload` |
| 몬스터 | `MythicMobs/Mobs/*.yml` | `/mm reload` |

- 파일에서 빠진 항목은 플러그인에 들어 있는 기본값으로 채워집니다.
- 모든 파일 맨 위에 항목 설명 주석이 있습니다. 색상은 `&` + 글자(`&c` 빨강, `&a` 연두, `&7` 회색 등), 값이 바뀌는 자리는 `{player}`처럼 중괄호로 표시됩니다.
- NPC는 `npcs.yml`이 기준입니다. 서버가 켜질 때와 `/설정리로드` 때 게임 안 NPC가 이 파일대로 만들어지고, 옮겨지고, 삭제됩니다. Citizens의 `saves.yml`은 직접 수정하지 않습니다.

## ⚙️ config.yml

맵 위치와 인증 설정입니다. 모든 좌표는 블록 좌표(`F3` 화면의 정수 좌표)입니다.

```yaml
auth:
  enabled: true        # false: 인증 없이 입장 (맵 수정·테스트 시 사용)
  room: {x, y, z}      # 인증 대기소 (맵 경계 밖에 배치)
  lock-size: 15        # 인증 중 이동 가능 범위 (한 변 길이, 블록)
  max-fail: 5          # 연속 실패 허용 횟수, 초과 시 퇴장
  gamemode: {waiting: ADVENTURE, after: SURVIVAL}   # 인증 중 / 인증 후 게임모드
  test-account: {...}  # 테스트 계정 (아래 주의사항 참고)

spawn:
  first: {x, y, z}     # 최초 스폰 = 월드 스폰 (/lobby, 부활 위치)

border:
  enabled: true        # false: 맵 경계 미사용
  corner1: {x, z}      # 영역의 대각선 꼭짓점 (순서 무관, 양 끝 블록 포함)
  corner2: {x, z}

quests:                # /퀘스트 표시 이름
  <오브젝티브 ID>: "<표시 이름>"
```

- `auth.enabled` 변경은 이미 접속 중인 플레이어에게는 적용되지 않고 다음 접속부터 적용됩니다.
- 맵 경계는 직사각형이며, 경계에 가까워지면 월드보더(파란 벽)가 표시되고 경계 밖으로는 이동할 수 없습니다. 텔레포트는 제한하지 않습니다.
- **테스트 계정**: `auth.test-account.enabled`가 `true`이고 아이디·비밀번호가 비어 있지 않으면, 그 아이디·비밀번호로 리로스쿨 확인 없이 인증됩니다. 기본값은 꺼짐이며, 운영 서버에서는 켜지 않습니다. 저장소가 공개이므로 실제 쓰는 아이디·비밀번호를 Git에 올리지 않습니다. 이 계정으로 인증되면 서버 콘솔에 기록이 남습니다.

## 🎮 게임 수치 (gameplay.yml)

숫자로 정하는 게임 규칙은 모두 이 파일에 있습니다.

```yaml
stats:
  starting-points: 5                 # 새 캐릭터의 자유 분배 포인트
  click-amount: 1                    # /stat 에서 클릭 한 번에 오르는 양 (shift-click-amount: Shift 클릭)
  attributes:                        # 5대 스탯(str, dex, intel, hp, wis)의 이름·아이콘·GUI 칸·시작 값
    str: {label: "근력", gui-name: "근력 (STR)", material: REDSTONE, slot: 20, starting: 1}
  max-hp: {base: 100, per-point: 15} # 최대 HP = base + 체력 스탯 x per-point
  max-mp: {base: 50, per-point: 10}  # 최대 MP = base + 지능 스탯 x per-point
  walk-speed: {...}                  # 민첩에 따른 걷기 속도와 상한
  mana-regen: {...}                  # 초당 마나 재생

leveling:
  max-level: 100
  required-exp: {base: 100, exponent: 2.5}   # 필요 경험치 = floor(base x 레벨 ^ exponent)
  level-up-points: {...}                      # 레벨업 때 지급되는 스탯 포인트 계산
  broadcast-every-levels: 5                   # 이 간격마다 레벨업을 서버 전체에 알림 (0이면 안 함)
  level-achievements: {5: level_5, ...}       # 레벨 도달 도전과제

rewards:                             # 처치·채굴·사망·PvP·동아리 협동 보상 (경험치, 확률, 포인트, 도전과제 연결)
rules:                               # 서바이벌 블록 파괴, 동물 스폰, 시간 건너뛰기(잠으로 밤 넘기기만 해당, /time 명령은 항상 가능), 배고픔, 폭발, 발광, PvP 규칙 (true/false)
world:                               # 게임 규칙(KEEP_INVENTORY 등), 날씨
```

- 스탯 ID(`str`, `dex`, `intel`, `hp`, `wis`)는 코드에 연결되어 있어 바꿀 수 없습니다. 이름·아이콘·위치·시작 값은 바꿀 수 있습니다.
- 보상의 `achievement`에는 `achievements.yml`의 도전과제 ID를 적습니다. 비워 두면 도전과제 없이 보상만 지급됩니다.
- 채굴 보상(`rewards.mining`)은 서바이벌에서 블록을 부술 수 없는 현재 규칙(`rules.survival-block-break: false`)에서는 서바이벌이 아닌 모드에서만 받을 수 있습니다.
- **레벨업 스탯 포인트**: `leveling.level-up-points`의 현재 값에서는 계산 결과가 음수가 되어 레벨업할 때 스탯 포인트가 오히려 줄어듭니다. 기존 코드의 계산식을 그대로 옮긴 것이며, 의도한 지급 규칙을 정해 개발 측에 전달합니다.
- 이미 접속 중인 플레이어의 최대 HP·MP와 걷기 속도는 다음 접속이나 스탯 변경 때 다시 계산됩니다.

## 🏫 동아리 (clubs.yml)

동아리 선택 GUI, 가입 시 스탯 보너스, 월드 랭킹판이 모두 이 목록 하나를 씁니다. 적은 순서가 점수가 같을 때의 랭킹 순서입니다.

```yaml
clubs:
  LOGIC:                     # 동아리 ID (영어 대문자)
    name: "LOGIC (수학)"      # GUI 에 보이는 이름
    color: "&b"
    icon: "📘"                # 랭킹 등에 쓰는 아이콘
    material: BOOK           # GUI 아이콘
    slot: 10                 # GUI 칸 번호 (다른 동아리와 겹치면 안 됨)
    bonus: {intel: 15, hp: 5}   # 가입 시 올라가는 스탯 (str, dex, intel, hp, wis)
```

- 새 동아리는 새 ID로 추가합니다. 동아리 ID를 바꾸거나 지우면 그 동아리로 이미 가입한 플레이어의 소속이 인식되지 않습니다.
- 가입 후 탈퇴해도 올라간 스탯은 회수되지 않습니다. (현재 기능 범위)
- 동아리 점수가 쌓이는 조건은 아직 없어서 랭킹은 모든 동아리가 0점입니다.

## ⚔️ 스킬 (skills.yml)

스킬은 지정한 재료와 이름의 아이템을 들고 우클릭하면 발동합니다. 스킬 종류(`FIREBALL`, `EARTHQUAKE`, `HOLY_BOMB`, `HEAL`)는 코드에 연결되어 있고, 쿨타임·마나·범위·피해량 같은 수치를 조정합니다. 항목 설명은 `skills.yml` 상단 주석을 참고합니다.

- 스킬 아이템은 `/아이템지급`이나 BetonQuest 보상으로 지급합니다. (아이템 이름이 `trigger.name`과 정확히 같아야 합니다)
- 스킬은 Shift+F 같은 키가 아니라, 위 아이템을 들고 우클릭하면 발동합니다. (도움말도 그렇게 안내합니다)

## 💬 문구 (messages.yml)

플레이어에게 보이는 알림·안내·GUI 제목·사이드바·Tab 목록·인증 안내 문구가 모두 이 파일에 있습니다.

```yaml
level-up:
  title: "&6&l★ LEVEL UP! ★ &eLv.{level} 달성!"    # {level} 은 새 레벨로 바뀝니다
scoreboard:
  lines:                                            # 사이드바(오른쪽 정보창). 한 줄이 목록 하나
    - "&e{player} &7Lv.{level}"
    - "&aEXP &7{exp-percent}%"
    - "{exp-bar}"                                   # 경험치 막대 (▰▰▰▱▱▱▱▱▱▱)
    - " "                                           # 빈 줄은 공백 한 칸
```

- 사이드바에는 레벨·EXP·소속·마나·스킬 쿨타임을 카드 모양으로 보여 줍니다. 스탯은 `/stat`, 동아리 랭킹은 월드 랭킹판(아래 "동아리 랭킹판")에서 봅니다.
- 쓸 수 있는 자리: `{player}` `{level}` `{club}` `{cooldown}` `{exp}` `{exp-required}` `{exp-percent}` `{exp-bar}` `{mp}` `{max-mp}` `{mp-bar}` (스탯 `{str}` `{dex}` `{int}` `{hp}` `{wis}`도 쓸 수 있지만 기본 화면에는 넣지 않았습니다)
- 막대 모양은 같은 `scoreboard` 아래의 `bar-length`(칸 수), `bar-char-filled`·`bar-char-empty`(칸 모양), `bar-exp-color`·`bar-mp-color`·`bar-empty-color`(색)로 바꿉니다.
- 사이드바는 최대 15줄까지만 보입니다.

- 중괄호 자리(`{level}`, `{player}` 등)는 지우거나 이름을 바꾸지 않습니다. 항목마다 쓸 수 있는 자리가 위 주석에 적혀 있습니다.
- 키 이름(왼쪽)을 바꾸거나 지우면 문구가 키 이름 그대로 보이고 서버 콘솔에 경고가 출력됩니다.
- 명령어 뒤에 붙이는 단어(`/club 탈퇴`, `/입장허용 열기·닫기`)도 여기서 바꿉니다. 사용법 문구에 적힌 단어와 같게 맞춥니다.

## 🗡️ 커스텀 아이템 (items.yml)

```yaml
items:
  jasmine_flower:            # 아이템 ID
    material: AZURE_BLUET    # 재료 (영어 대문자)
    name: "&d자스민 꽃"
    lore:                    # 설명문 (한 줄 = 항목 하나)
      - "&7으깨어 상처에 바르면 통증이 가라앉는다."
    unbreakable: false
```

- 지급: `/아이템지급 <플레이어> <아이템ID>`
- 아이템의 기능은 `effects` 항목에 정의합니다. 우클릭(`RIGHT_CLICK`) 또는 공격 적중(`HIT`) 시 체력 회복, 포션 효과, 밀쳐내기, 띄우기를 수치(회복량, 지속시간, 쿨타임 등)와 함께 설정할 수 있습니다. 항목 설명은 `items.yml` 상단 주석과 [ITEM_LIST.md](ITEM_LIST.md)를 참고합니다.
- 새 아이템은 새 ID(영어 소문자)로 추가합니다. `effects`가 없으면 효과 없는 장식용 아이템입니다. 표현할 수 없는 새로운 종류의 효과는 개발 측에 요청합니다.
- 이름·설명은 지급 시점에 아이템에 복사되므로, 이미 지급된 아이템은 변경되지 않고 이후 지급분부터 반영됩니다. 효과(`effects`)는 ID로 읽기 때문에 이미 지급된 아이템에도 바로 적용됩니다.
- 잘못된 이름(재료, 효과음, 포션 등)은 해당 부분만 무시되고 서버 콘솔에 `[items.yml]` 경고가 출력됩니다. 재료 이름이 잘못되면 해당 아이템은 생성되지 않습니다.

## 🏆 도전과제 (achievements.yml)

```yaml
achievements:
  diamond:                   # 도전과제 ID
    material: DIAMOND        # GUI 표시 아이템
    title: "진짜 보물 찾기"
    description: "깊은 곳에서 다이아몬드를 발견했습니다."
    popup: "..."             # (선택) 달성 알림 문구, 없으면 description
    show-in-gui: false       # (선택) /도전과제 목록에서 숨김
```

- 이름·설명을 수정하면 `/도전과제` GUI와 달성 알림에 함께 반영됩니다. GUI 제목·진행률·알림 큰 글씨 같은 공통 문구는 같은 파일의 `texts`에 있습니다.
- 도전과제를 언제 주는지는 `gameplay.yml`에서 이 ID로 연결합니다. (`rewards.kill`, `rewards.mining.special`, `rewards.death`, `rewards.pvp-win`, `rewards.club-coop`의 `achievement`, `leveling.level-achievements`) 새 ID를 만들어도 연결하지 않으면 달성되지 않습니다.
- `join_club`, `stat_up`, `first_npc`는 연결할 수 있는 조건이 없어 항상 미달성으로 표시됩니다. 조건 종류 추가는 개발 측에 요청합니다.

## 📖 도움말 (help.yml)

- `lines`: 전체 플레이어, `op-lines`: OP 추가 노출, `footer`: 마지막 줄.
- 한 줄이 목록 항목 하나이며 빈 줄은 `""`로 작성합니다. 줄 안의 큰따옴표는 `\"`로 이스케이프합니다.

## 📜 퀘스트와 NPC 추가

예시: NPC `slime_hunter`가 슬라임 5마리 처치를 의뢰하고, 보상으로 커스텀 아이템 `slime_jelly`를 지급하는 퀘스트.

### 1. 보상 아이템 정의 (items.yml)

```yaml
  slime_jelly:
    material: SLIME_BALL
    name: "&a말랑한 슬라임 젤리"
    lore:
      - "&7슬라임에게서 얻은 쫀득한 젤리."
    unbreakable: false
```

### 2. NPC 추가 (npcs.yml)

게임에서 NPC를 세울 자리에 서서 입력합니다. (OP)

```text
/엔피씨 추가 slime_hunter &a슬라임 사냥꾼
```

`npcs.yml` 맨 아래에 항목이 자동으로 적히고 NPC가 생성됩니다.

**위치는 게임에서 명령으로 관리합니다.** 좌표를 파일에 직접 적지 않습니다.

| 명령 (OP) | 설명 |
|---|---|
| `/엔피씨 추가 [키] [이름]` | 서 있는 자리에 NPC 추가 |
| `/엔피씨 이동 [키]` | NPC를 지금 서 있는 자리로 이동 (바라보는 방향 포함) |
| `/엔피씨 삭제 [키]` | NPC 삭제 |
| `/엔피씨 목록` | NPC 목록과 좌표 |

명령을 쓰면 `npcs.yml`의 좌표도 자동으로 바뀌고, 파일의 주석은 그대로 남습니다. 이름과 스킨은 파일에서 수정합니다.

```yaml
npcs:
  slime_hunter:
    name: "&a슬라임 사냥꾼"
    skin: Notch                                       # 선택
    location: {x: 310.5, y: -61, z: 162.5, yaw: 180}  # /엔피씨 이동 으로 자동 갱신
    look-at-player: true
    conversation: slime_hunter                        # conversations/slime_hunter.yml
```

- 이름·스킨을 고치고 `/설정리로드`를 입력하면 반영됩니다.
- 사람이 아닌 모습으로 만들려면 `type`을 씁니다. 예) `type: CAT` (고양이). 고양이는 `variant`(무늬: `TABBY`, `BLACK`, `SIAMESE`, `BRITISH_SHORTHAIR` 등)와 `sitting: true`(앉은 자세)도 쓸 수 있고, `skin`은 사람(`PLAYER`)에만 적용됩니다. `incheon_science_cat`이 예시입니다.
- 맵 위치가 바뀌면 `offset`의 x, y, z만 고쳐 모든 NPC를 한 번에 옮깁니다.
- BetonQuest와의 연결(Citizens ID)은 서버가 자동으로 처리하므로 `main.yml`에 쓰지 않습니다.
- NPC마다 이름 색을 다르게 정할 수 있습니다. `name`에 색 코드(`&` + 글자)를 씁니다. 예) `&c`(빨강), `&b`(하늘), `&a`(연두), `&d`(분홍), `&0`(검정), `&l`(굵게). 검정(`&0`)이나 아주 어두운 색은 이름표 배경과 겹쳐 읽기 어려울 수 있습니다.

### 3. 퀘스트 (main.yml)

각 섹션의 기존 제목 아래에 항목을 추가합니다. (섹션을 중복 선언하지 않습니다)

```yaml
events:
  start_slime_quest: "folder slime_start_obj,slime_start_msg"
  slime_start_obj: "objective start slime_quest_obj"
  slime_start_msg: "command msg %player% &e[시스템] 새로운 퀘스트를 받았습니다! (슬라임 사냥꾼)"
  slime_quest_reward: "folder slime_msg,slime_give"
  slime_msg: "command msg %player% &a[시스템] 슬라임 사냥꾼의 퀘스트를 완료했습니다!"
  slime_give: "command 아이템지급 %player% slime_jelly"

objectives:
  slime_quest_obj: "mobkill SLIME 5 events:slime_quest_reward"

```

| 목표 유형 | 형식 |
|---|---|
| 몬스터 처치 | `mobkill <몹 이름> <마릿수> events:<완료 이벤트>` |
| 블록 채굴 | `block <블록 이름> -<개수> events:<완료 이벤트>` (개수 앞에 `-`) |
| 아이템 제작 | `craft <아이템> <개수> events:<완료 이벤트>` |

바닐라 아이템 보상은 `command give %player% emerald 3` 형식을 사용합니다.

### 4. 대화 파일 (conversations/slime_hunter.yml)

```yaml
conversations:
  slime_hunter:
    quester: "슬라임 사냥꾼"
    first: start
    NPC_options:
      start:
        text: "&a[슬라임 사냥꾼]&f 어서 와, 신입! 요즘 슬라임이 너무 불어났어. 좀 도와줄 수 있겠어?"
        pointers: quest1,q_no
      q1:
        text: "&a[슬라임 사냥꾼]&f 슬라임을 5마리만 처치해 줘. 도와주면 쫀득한 젤리를 줄게!"
        pointers: accept,q_no
      q_accept:
        text: "&a[슬라임 사냥꾼]&f 고마워! 부탁할게."
        events: start_slime_quest
    player_options:
      quest1:
        text: "네, 도와드릴게요!"
        pointers: q1
      accept:
        text: "슬라임 5마리, 맡겨 주세요."
        pointers: q_accept
      q_no:
        text: "지금은 어려워요."
```

- 파일 이름과 `npcs.yml`의 `conversation` 값이 일치해야 합니다.
- `pointers`는 다음에 이어질 선택지의 이름이며, 철자가 틀리면 대화가 중단됩니다.
- `events:`에 지정한 이벤트는 해당 대사가 출력될 때 실행됩니다.

### 5. `/퀘스트` 표시 이름 (config.yml)

```yaml
quests:
  slime_quest_obj: "슬라임 사냥꾼 - 슬라임 사냥"
```

키는 `main.yml`의 오브젝티브 ID와 동일해야 합니다.

### 6. 적용

`배포.bat` 실행 후 게임에서 `/bq reload`, `/설정리로드`를 입력합니다. NPC를 우클릭해 대화·수락·처치·보상 지급 순으로 확인합니다.

현재 NPC 목록은 [NPC_LIST.md](NPC_LIST.md)를 참고합니다.

## 🏆 동아리 랭킹판

동아리 점수 순위는 화면 오른쪽 정보창이 아니라, 월드에 떠 있는 큰 글씨로 보여 줍니다. (정보창에는 레벨·EXP·소속·마나·스킬 쿨타임만 표시됩니다. 스탯은 `/stat`에서 봅니다)

| 명령 (OP) | 설명 |
|---|---|
| `/랭킹판 설치` | 바라보는 벽(12칸 이내)에 랭킹판을 붙임 |
| `/랭킹판 삭제` | 랭킹판 삭제 |

- 설치하면 `ranking.yml`의 `world`, `location`이 자동으로 적힙니다. 위치가 어색하면 다른 벽을 바라보고 다시 설치합니다.
- 글씨 크기(`scale`), 제목(`title`), 한 줄 모양(`line`), 갱신 간격(`update-seconds`)은 `ranking.yml`에서 고치고 `/설정리로드`를 입력합니다.
- 동아리 점수가 오르는 규칙은 아직 없어서 지금은 모두 0점으로 표시됩니다.

**벽 꾸미기 (추천 블록)**

글씨는 흰색이라 밝은 벽 앞에서는 잘 안 보입니다. 어두운 바탕에 빛나는 테두리를 두르면 가장 잘 보입니다. 글씨 자체는 항상 밝게 나오므로(`brightness`), 벽은 분위기용입니다.

| 용도 | 추천 블록 | 느낌 |
|---|---|---|
| 바탕(글씨 뒤) | 검은색 콘크리트, 폴리싱 블랙스톤, 어두운 프리즈마린 | 글씨가 또렷함 |
| 빛나는 테두리 | 바다 랜턴 | 하얀 푸른빛, 가장 깔끔 (밝기 15) |
| | 발광석 / 빛버섯(Shroomlight) | 따뜻한 노란빛 |
| | 개구리광(Froglight) 3종 | 노랑/초록/분홍빛, 장식용으로 예쁨 |
| 빛만 필요할 때 | 빛 블록 (`/give @s light`) | 보이지 않는 광원. 바탕 뒤에 숨겨 두면 깔끔함 |

흰색 테라코타처럼 빛나지 않는 밝은 블록은 글씨와 겹쳐 보이기 어렵습니다.
- 사이드바 줄 구성은 `messages.yml`의 `scoreboard.lines`에서 고칩니다.

## 🛠️ 수동 조절 명령 (OP)

점수나 스탯을 테스트·이벤트용으로 직접 바꿀 때 씁니다. 두 명령 모두 탭(Tab)으로 자동완성됩니다.

### 동아리 점수

| 명령 | 설명 |
|---|---|
| `/동아리점수 목록` | 동아리별 점수 |
| `/동아리점수 설정 LOGIC 100` | 점수를 그 값으로 맞춤 |
| `/동아리점수 추가 WIN 10` | 점수를 더함 (음수면 뺌) |
| `/동아리점수 초기화 [동아리\|전체]` | 0점으로 |

점수는 서버를 껐다 켜도 `plugins/ishsMinecraftRpg/club-scores.yml`에 남습니다. 랭킹판은 몇 초 안에 바뀝니다.

### 플레이어 스탯 (접속 중인 플레이어만)

| 명령 | 설명 |
|---|---|
| `/스탯조정 도혜 정보` | 레벨, 경험치, 스탯 포인트, 스탯, 소속 확인 |
| `/스탯조정 도혜 레벨 설정 30` | 레벨을 그 값으로 (1~최대 레벨) |
| `/스탯조정 도혜 경험치 추가 500` | 경험치를 더함 |
| `/스탯조정 도혜 스탯포인트 추가 10` | 분배할 스탯 포인트를 더함 |
| `/스탯조정 도혜 str 설정 50` | 스탯을 그 값으로 (`str`, `dex`, `intel`, `hp`, `wis` 또는 `gameplay.yml`의 스탯 이름) |
| `/스탯조정 도혜 동아리 LOGIC` | 소속 변경 (`없음`이면 탈퇴) |
| `/스탯조정 도혜 초기화` | 레벨 1, 시작 스탯, 소속 없음으로 되돌림 |

- `설정`은 값을 그대로 맞추고, `추가`는 현재 값에 더합니다(음수면 뺌).
- 범위를 벗어나는 값(레벨 0, 음수 스탯 등)은 거절되고 아무것도 바뀌지 않습니다.
- 소속을 바꿔도 동아리 가입 보너스 스탯은 자동으로 조정되지 않습니다. 필요하면 스탯을 따로 맞춥니다.
- 바뀐 값은 최대 HP/MP 등에 바로 반영되고 저장됩니다.

## 🔧 문제 해결

| 증상 | 확인 사항 |
|---|---|
| `/설정리로드` 후 값이 바뀌지 않음 | YAML 들여쓰기, 콜론(`:`) 뒤 공백 1칸 |
| `/퀘스트`에 퀘스트가 표시되지 않음 | `config.yml`의 `quests` 키와 `main.yml` 오브젝티브 ID 일치 여부 |
| NPC가 생기지 않음 | `npcs.yml` 항목의 `location`(x, y, z), 키 형식(영어 소문자), 서버 콘솔의 `[npcs.yml]` 경고 |
| NPC 우클릭 시 반응 없음 | `conversation` 이름과 `conversations/<이름>.yml` 파일명 일치 여부, `/bq reload` 실행 여부 |
| 대화가 중간에 끊김 | `pointers` 이름이 `NPC_options`/`player_options`에 존재하는지 |
| BetonQuest 로딩 오류 | 서버 콘솔의 오류 메시지 (대부분 들여쓰기 문제) |
| 아이템이 생성되지 않음 | 서버 콘솔의 `[items.yml]` 경고 (재료 이름 오타) |

## ✅ 설정 검증

서버를 켜지 않고도 설정 파일의 연결과 형식을 확인할 수 있습니다. (Java와 Gradle이 설치된 PC 기준)

```bash
./gradlew test
```

- 문구 키 철자, 문구 안 `{자리표시자}`, 도전과제·퀘스트·NPC 연결, GUI 칸 겹침, 잘못된 재료 이름, BetonQuest 이벤트 참조를 확인합니다.
- 수치를 바꿔도 이 검증은 실패하지 않습니다. 연결이 끊기거나 형식이 틀린 경우에만 실패하며, 실패 메시지에 어느 항목이 문제인지 표시됩니다.
- `./gradlew parityTest`는 설정 기본값이 설정 파일로 옮기기 전 코드의 값과 같은지 확인하는 개발용 검증입니다. 기획 의도로 수치를 바꾸면 실패하는 것이 정상입니다.
