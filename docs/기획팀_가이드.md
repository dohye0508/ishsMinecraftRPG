# 기획팀 가이드

코드(Java)를 건드리지 않고 **텍스트 파일의 값만 고쳐서** 서버 내용을 바꾸는 방법입니다.
수정할 파일은 모두 저장소의 **`configs\` 폴더 하나**에 모여 있습니다. 서버 폴더를 직접 열어서 고치지 마세요.

## 0. 작업 순서 (매번 똑같습니다)

1. `configs\` 안의 파일을 고칩니다.
2. `configs\배포.bat`을 더블클릭합니다. (바뀐 파일만 서버로 복사되고, 서버의 기존 파일은 자동 백업됩니다)
   - 무엇이 바뀌는지만 먼저 보고 싶으면 `미리보기_배포.bat`을 쓰세요.
3. 게임에서 OP가 아래를 입력해 적용합니다. (서버가 꺼져 있었다면 켜기만 하면 됩니다)
   - `/bq reload` — 퀘스트, 대화
   - `/설정리로드` — config, 아이템, 도전과제, 도움말
4. 확인이 끝나면 Git에 올립니다. (`git add configs` → `git commit` → `git push`)

폴더 구조와 `배포.bat`의 자세한 설명은 [`configs/README.md`](../configs/README.md)를 보세요.

## 1. 어디서 무엇을 바꾸나

| 바꾸고 싶은 것 | 파일 (`configs\` 기준) | 서버에 적용 (배포.bat 후) |
|---|---|---|
| 스폰, 인증 대기소, 맵 경계, 인증 켜고 끄기, 퀘스트 표시 이름 | `ishsMinecraftRpg\config.yml` | `/설정리로드` |
| 커스텀 아이템 이름, 재료, 설명 | `ishsMinecraftRpg\items.yml` | `/설정리로드` |
| 도전과제 이름, 설명, 달성 알림 문구 | `ishsMinecraftRpg\achievements.yml` | `/설정리로드` |
| `/도움말` 문구 | `ishsMinecraftRpg\help.yml` | `/설정리로드` |
| 퀘스트 내용(목표, 보상), NPC 연결 | `BetonQuest\QuestPackages\default\main.yml` | `/bq reload` |
| NPC 대사, 선택지 | `BetonQuest\QuestPackages\default\conversations\이름.yml` | `/bq reload` |
| 몬스터 | `MythicMobs\Mobs\*.yml` | MythicMobs 리로드 (`/mm reload`) |
| NPC 위치/모습 | 게임 안에서 Citizens 명령(`/npc ...`) | 바로 저장됨 |

> NPC의 위치와 모습은 게임 안 `/npc` 명령으로 정하며 서버의 `Citizens\saves.yml`에 저장됩니다. 이 파일은 직접 고치지 마세요. (서버가 종료할 때 덮어씁니다) 소유자 정보가 들어 있어 Git에도 올리지 않습니다.

## 2. config.yml 항목

모든 좌표는 **블록 좌표**입니다. 게임에서 `F3`을 눌렀을 때 보이는 `XYZ`의 정수 부분을 적으세요.

```yaml
auth:
  enabled: true        # true: 리로스쿨 인증 사용 / false: 인증 없이 입장 (맵 수정할 때 끄기)
  room: {x, y, z}      # 인증 대기소 위치 (맵 경계 밖에 두면 됩니다)
  lock-size: 15        # 인증 중 움직일 수 있는 범위(한 변 길이)

spawn:
  first: {x, y, z}     # 최초 스폰 = 월드 스폰(/lobby, 부활 위치)

border:
  enabled: true        # false면 맵 경계를 쓰지 않음
  corner1: {x, z}      # 영역의 대각선 꼭짓점 두 곳
  corner2: {x, z}      # (순서 상관없음, 양 끝 블록도 포함)

quests:                # /퀘스트 에 보일 이름
  오브젝티브ID: "화면에 보여줄 이름"
```

- 값을 고치고 `/설정리로드`를 입력하면 바로 반영됩니다.
- 인증 `enabled`를 바꾼 경우, **이미 접속해 있는 사람이 아니라 다음 접속부터** 적용됩니다.
- 맵 경계는 직사각형이고, 가까이 가면 파란 벽(월드보더)이 보입니다. 경계 밖으로는 못 나갑니다.

## 3. 새 퀘스트 추가하기

예시: "슬라임 5마리 잡기" 퀘스트를 만든다고 가정합니다. 이름은 `slime_quest`로 합니다.

### (1) `main.yml`에 이벤트와 목표 추가

`events:` 아래에 시작/보상 이벤트를 추가합니다. (기존 `logic_*` 항목을 복사해서 이름만 바꾸면 편합니다)

```yaml
events:
  start_slime_quest: "folder slime_start_obj,slime_start_msg"
  slime_start_obj: "objective start slime_quest_obj"
  slime_start_msg: "command msg %player% &e[시스템] 방금 새로운 퀘스트를 받았습니다!"
  slime_quest_reward: "folder slime_msg,slime_give"
  slime_msg: "command msg %player% &a[시스템] 퀘스트를 완료했습니다!"
  slime_give: "command give %player% emerald 3"
```

`objectives:` 아래에 목표를 추가합니다.

```yaml
objectives:
  slime_quest_obj: "mobkill SLIME 5 events:slime_quest_reward"
```

- 몹 처치: `mobkill 몹이름 마릿수 events:완료이벤트`
- 블록 채굴: `block 블록이름 -개수 events:완료이벤트` (개수 앞에 `-`를 붙입니다)
- 아이템 제작: `craft 아이템 개수 events:완료이벤트`

### (2) 대화 파일에서 시작 이벤트 연결

NPC 대화 파일의 마지막 선택지에 `events: start_slime_quest`를 넣으면 대화가 끝날 때 퀘스트가 시작됩니다.
(예시는 `conversations\logic_buzzang.yml`의 `q_accept` 부분 참고)

### (3) `config.yml`의 `quests`에 표시 이름 한 줄 추가

```yaml
quests:
  slime_quest_obj: "슬라임 사냥"
```

### (4) 적용

`/bq reload` → `/설정리로드` 를 차례로 입력합니다.

## 4. 새 NPC 추가하기

1. 만들 위치에 서서 `/npc create 이름` 을 입력합니다.
2. NPC ID를 확인합니다. (`/npc list` 로 목록과 ID를 볼 수 있습니다)
3. 위치를 옮기려면 NPC를 선택(`/npc select`)한 뒤, 옮길 곳에 서서 `/npc tphere` 를 입력합니다.
4. `main.yml`의 `npcs:` 항목에 `키: "citizens ID"` 한 줄을 추가합니다.
5. `main.yml`의 `npc_conversations:` 항목에 `키: 대화파일이름` 한 줄을 추가합니다.
6. `conversations\대화파일이름.yml` 파일을 만들고 대사를 적습니다. (기존 파일을 복사해서 고치면 편합니다)
7. `/bq reload` 로 적용합니다.

## 5. 아이템, 도전과제, 도움말 문구 수정하기

세 파일 모두 파일 맨 위에 **설명 주석**이 있으니 먼저 읽어 보세요. 색상은 `&` + 글자로 씁니다. (예: `&c` 빨강, `&a` 연두, `&7` 회색)

### 커스텀 아이템 (`items.yml`)

```yaml
items:
  jasmine_flower:            # 아이템 ID (바꾸지 마세요)
    material: AZURE_BLUET    # 재료 (영어 대문자)
    name: "&d자스민 꽃"       # 아이템 이름
    lore:                    # 설명문 (한 줄 = 목록 하나)
      - "&7으깨어 상처에 바르면 통증이 가라앉는다."
    unbreakable: false       # true면 내구도가 닳지 않음
```

- 이름, 재료, 설명은 자유롭게 바꿀 수 있습니다. 지급은 `/아이템지급 [플레이어] [아이템ID]`.
- **효과는 ID에 코드가 연결되어 있습니다.** 기존 6개 ID(`demerit_card`, `wanil_staff`, `jasmine_flower`, `schema`, `changbong_spear`, `changbong_rod`)는 바꾸지 마세요. 바꾸면 효과가 사라집니다.
- 새 ID를 추가하면 **효과 없는 장식용 아이템**이 만들어집니다. 효과가 필요하면 개발자에게 요청하세요.
- 고쳐도 **이미 플레이어가 가진 아이템은 바뀌지 않고**, 새로 지급하는 것부터 바뀝니다.
- 재료 이름이 틀리면 서버 콘솔에 경고가 나오고 그 아이템은 만들어지지 않습니다.

### 도전과제 (`achievements.yml`)

```yaml
achievements:
  diamond:                   # 도전과제 ID (바꾸지 마세요)
    material: DIAMOND        # 달성했을 때 GUI에 보이는 아이템
    title: "진짜 보물 찾기"
    description: "깊은 곳에서 다이아몬드를 발견했습니다."
    popup: "..."             # (선택) 달성했을 때 화면에 뜨는 문구, 없으면 description
    show-in-gui: false       # (선택) false면 /도전과제 목록에서 숨김
```

- 이름과 설명을 바꾸면 `/도전과제` GUI와 달성 알림에 모두 반영됩니다.
- **달성 조건은 ID에 코드가 연결되어 있습니다.** ID를 바꾸거나 새로 만들어도 달성 조건은 생기지 않습니다. 새 도전과제 조건은 개발자에게 요청하세요.
- 현재 `join_club`, `stat_up`, `first_npc`는 달성 처리 코드가 없어 항상 미달성으로 보입니다.

### 도움말 (`help.yml`)

- `lines`: 모든 플레이어에게 보이는 줄, `op-lines`: OP에게만 추가로 보이는 줄, `footer`: 마지막 줄들입니다.
- 한 줄이 목록 하나이고 빈 줄은 `""`로 적습니다.
- 줄 안에 큰따옴표(`"`)를 쓰려면 `\"`로 적으세요.

## 6. 맵(월드)을 바꿀 때 체크리스트

- [ ] `config.yml`의 `spawn.first`, `auth.room`, `border` 좌표가 새 맵에 맞는지 확인하고 `/설정리로드`
- [ ] NPC 위치 다시 배치 (`/npc tphere`)
- [ ] 퀘스트에서 위치를 쓰는 부분이 있다면 새 좌표로 수정
- [ ] 인증 대기소가 맵 경계 밖에 있는지 확인

## 7. 문제가 생겼을 때

- `/설정리로드` 후에도 안 바뀌면 `config.yml`의 들여쓰기(띄어쓰기)가 틀렸는지 확인하세요. 콜론(`:`) 뒤에는 한 칸을 띄웁니다.
- 퀘스트가 `/퀘스트`에 안 보이면 `quests`의 키가 `main.yml`의 오브젝티브 ID와 정확히 같은지 확인하세요.
- NPC에게 말을 걸어도 반응이 없으면 `main.yml`의 `npcs:` 번호가 실제 NPC ID와 같은지 확인하고 `/bq reload` 하세요.
